## Summary

This is the second audit of the Analytics suite following fixes for all 9 findings from the first audit (2026-08-12). The prior Critical issues (chart accessibility, color-only signal) and Major issues (filter toolbar lockout, missing KPI tooltips, mobile overflow, tab param loss) are all resolved. The codebase is now in significantly better shape. This sweep identified **0 Critical**, **3 Major**, and **5 Minor** new issues, mostly around empty state UX design, visual hierarchy at tablet breakpoints, and interaction affordance polish.

## Resolved since last audit

- **Accessibility — Donut Chart Screen Reader & Keyboard Access Barrier** — resolved. `pie-chart.tsx` now has `role="img"`, `aria-label`, focusable legend items with `tabIndex={0}` and `focus-visible:ring-2`.
- **Color & Contrast — Color-Only Signal in Unsuccessful Endings Progress Bar** — resolved. `blackhole-breakdown-card.tsx` ghosted segment now has diagonal CSS stripe pattern overlay and `role="img"` with descriptive `aria-label`.
- **Navigation — Filter State Persistence & Reset Friction** — resolved. `tabs.tsx` now preserves all URL search params via `new URLSearchParams(searchParams.toString())`.
- **Content & Microcopy — Unclarified Metrics & Missing Tooltips in KPI Summary** — resolved. All four KPI cards in `kpi-summary.tsx` have `<HelpCircle>` popover tooltips with formulas and benchmarks.
- **Responsive Design — Platform ROI Dashboard Mobile Overflow** — resolved. `platform-roi-dashboard.tsx` card headers now use `flex-col sm:flex-row` with `flex-wrap` and `truncate` on text.
- **Task-Flow Friction — Misleading Empty State when Filters Yield Zero Results** — resolved. `status-per-platform/page.tsx` now always renders `AnalyticsFilter` toolbar before the conditional empty/data content.
- **Accessibility — Inconsistent Heading Hierarchy Across Analytics Cards** — resolved. `card.tsx` `CardTitle` now renders `<h3>` instead of `<div>`.
- **Interaction & Affordance — Filter Reset Touch Target Size** — resolved. Reset button now uses `min-h-[44px] sm:min-h-0 sm:h-8`.
- **Perceived Performance — Missing Loading Skeletons on Filter State Changes** — resolved. `analytics-filter.tsx` now uses `useTransition` with `Loader2` spinner during filter navigation.

## New findings

### Task-Flow Friction — Empty State Doesn't Distinguish "Filtered to Zero" from "No Data at All"
- **Severity**: Major
- **Where**: `app/(pages)/analytics/status-per-platform/page.tsx` (lines 40–51)
- **Persona affected**: Alex (filtering by a specific month that returns zero results)
- **Problem**: While the filter toolbar is now always visible (prior fix), the empty state message is identical for both "no applications exist at all" and "no applications match the current filter." When `statusPerPlatform.length === 0 && !month && !year`, the generic "No applications found" card shows — but when the user has a filter applied and data is empty, `PlatformRoiDashboard` renders its own internal empty state ("No platform application data found for the selected period") which is a separate, inconsistent visual. More critically, neither empty state includes a "Clear Filters" button inline. Visible in `status-per-platform/375w.png`.
- **Fix**: Add a third branch: when `statusPerPlatform.length === 0 && (month || year)`, render a distinct empty state card saying "No applications found for [Month] [Year]" with a `<Button onClick={clearFilters}>Clear Filters</Button>` inline. This requires making the page a client component or extracting the conditional into a client wrapper.

### Visual Hierarchy & Layout — Strategy Coaching Cards Uneven Height at Tablet (768px)
- **Severity**: Major
- **Where**: `app/(pages)/analytics/overview/page.tsx` (line 136) — `grid grid-cols-1 md:grid-cols-3 gap-4`
- **Persona affected**: Sam (browsing on tablet)
- **Problem**: At 768px viewport, the Strategy Coaching section renders three cards (Best Platform, Ghosting Risk, ATS Domain) in a `md:grid-cols-3` grid. The `md` breakpoint is 768px in Tailwind, so these three cards are forced into equal-width columns that are each ~213px wide. Card titles like "BEST PERFORMING PLATFORM" and "ATS Domain Performance" wrap awkwardly across two lines, and the card content areas have very different heights — the Ghosting Risk card has 3 lines of content while Best Platform has 1 line. Visible in `overview/768w.png` where the three cards appear cramped and vertically misaligned.
- **Fix**: Change the breakpoint to `lg:grid-cols-3` so the three-column layout only activates at >=1024px. At tablet (768px), a `sm:grid-cols-2` intermediate grid (with the third card spanning full width) would give each card enough horizontal room.

### Content & Microcopy — Insights Page "No platform ROI data available" is Ambiguous
- **Severity**: Major
- **Where**: `app/(pages)/analytics/insights/page.tsx` (lines 100–103) — Platform Interview Yield Leaderboard empty state
- **Persona affected**: Sam (first-time user)
- **Problem**: The Platform Interview Yield Leaderboard card on the Strategic Insights page shows "No platform ROI data available" as its empty state. This is identical phrasing regardless of whether the user has zero applications total or just hasn't had any interviews yet. Sam doesn't know if they need to add applications, wait for interview invites, or if something is broken. There's no CTA to help them take the next step.
- **Fix**: Differentiate the empty states: "Add job applications to start tracking platform interview yield" (with a link to `/applications`) when no applications exist, vs. "Track your first interview to unlock platform yield metrics" when applications exist but no interviews are recorded.

### Typography — Section Header Text Too Small at All Viewports
- **Severity**: Minor
- **Where**: `app/(pages)/analytics/overview/page.tsx` (lines 109, 127, 143) — section `<h2>` elements
- **Persona affected**: Alex & Sam
- **Problem**: Section headers ("KEY PERFORMANCE RATES", "STRATEGY COACHING", "TRENDS & STATUS") use `text-sm font-bold uppercase tracking-wider text-muted-foreground`. At `text-sm` (14px), these section dividers are the same size as body description text, making them easy to miss when scanning the page. The combination of small size + uppercase + muted color makes them function more like category labels than section headings. Visible in `overview/1440w.png` where section headers blend into the card content above and below them.
- **Fix**: Increase to `text-base` (16px) or `text-sm` with a slightly stronger foreground color (`text-foreground/70` instead of `text-muted-foreground`) to create more visual separation between sections.

### Interaction & Affordance — Sort Buttons in Platform ROI Have No Active Visual Indicator Beyond Color
- **Severity**: Minor
- **Where**: `app/(pages)/analytics/components/platform-roi-dashboard.tsx` (lines 182–213) — sort buttons
- **Persona affected**: Alex (power user sorting platforms)
- **Problem**: The four sort buttons ("Volume", "Interview Rate", "Response Rate", "Name") toggle between `variant="secondary"` (active) and `variant="ghost"` (inactive). The visual difference between these states is subtle — `secondary` adds a light background while `ghost` is transparent. There's no underline, bold weight change, or icon indicator to reinforce which sort is currently active. On a quick glance, the active state doesn't stand out.
- **Fix**: Add `font-semibold` to the active state and `font-normal` to the inactive state, or add a small underline indicator (`border-b-2 border-primary`) on the active button.

### Accessibility — YearlyTrendsCard Tab Switcher Uses `<button>` Without ARIA Tab Pattern
- **Severity**: Minor
- **Where**: `app/(pages)/analytics/components/yearly-trends-card.tsx` (lines 61–89)
- **Persona affected**: Alex (keyboard/screen reader user)
- **Problem**: The "Status Breakdown" / "Total Volume" tab switcher uses plain `<button>` elements without `role="tablist"`, `role="tab"`, `aria-selected`, or `role="tabpanel"` on the content area. Screen readers announce these as generic buttons rather than tabs, and keyboard users don't get arrow-key navigation between tabs as expected by the ARIA tabs pattern. The `aria-selected` state is also missing, so screen readers can't report which tab is active.
- **Fix**: Add `role="tablist"` to the container div, `role="tab"` + `aria-selected={activeTab === "status"}` to each button, and `role="tabpanel"` to the `<CardContent>` area. Add `onKeyDown` handler for left/right arrow key switching between tabs.

### Color & Contrast — Muted Foreground on Light Background May Be Under WCAG AA for Small Text
- **Severity**: Minor
- **Where**: Multiple components — `best-platforms-card.tsx` (line 37), `ghosting-risk-card.tsx` (line 32), `domain-leaderboard-card.tsx` (line 29), `role-targeting-card.tsx` (line 27)
- **Persona affected**: Sam (low-vision user in light mode)
- **Problem**: Empty state text uses `text-sm text-muted-foreground` at 14px. Depending on the theme's `--muted-foreground` HSL value, this can fall near the WCAG AA boundary of 4.5:1 contrast ratio for normal text. In the light theme visible in `overview/1440w.png`, the "Apply to more jobs to see platform insights" and "No domain data available" text appears as a medium gray on near-white card backgrounds.
- **Fix**: Verify the actual computed contrast ratio of `text-muted-foreground` against `bg-card` in light mode. If below 4.5:1, darken `--muted-foreground` slightly or use `text-foreground/60` as a safe minimum for body-sized text.

### Visual Hierarchy & Layout — Insights Page Lacks Visual Anchoring When All Sections Are Empty
- **Severity**: Minor
- **Where**: `app/(pages)/analytics/insights/page.tsx` — full page, `insights/1440w.png`
- **Persona affected**: Sam (first-time user with no data)
- **Problem**: When a new user visits Strategic Insights with zero applications, every section shows empty state text: "No role targeting data available", "No unreturned or rejected applications recorded", "No platform ROI data available." The page is a column of three cards with gray placeholder text and nothing actionable. There's no visual illustration, no onboarding guidance, and no hierarchy indicating which card matters most or what to do first. The page feels abandoned rather than awaiting data. Visible in `insights/1440w.png`.
- **Fix**: Add a top-level onboarding banner (only when all three sections are empty) that explains what Strategic Insights will show once data is available, with a primary CTA like "Start Tracking Applications" linking to `/applications`. This gives Sam a clear next step instead of three separate dead ends.
